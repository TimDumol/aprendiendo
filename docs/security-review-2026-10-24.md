# Security review — 24 October 2026

Scope: Aprendiendo's committed application and dependencies, production shared Caddy, Pocket ID, exposed listeners, and container isolation. Existing staged feature work was excluded using a separate release checkout.

## Findings and remediation

- Production Caddy 2.11.4 falls within [GHSA-8qx7-j2v2-x6q5](https://github.com/caddyserver/caddy/security/advisories/GHSA-8qx7-j2v2-x6q5), fixed in 2.11.5. Upgrade to 2.11.7 (digest pinned in Ansible). Add a read-only root filesystem, process limit, bounded Docker logs, 10-second header timeout, 64 KB header limit, and two-minute idle timeout. Existing capability removal, loopback admin API, TLS and HSTS remain enabled. Streaming responses have no new total-duration limit.
- Production Pocket ID 2.12.0 falls within the PAR enforcement bypass [GHSA-fg8g-5j43-phc5](https://github.com/pocket-id/pocket-id/security/advisories/GHSA-fg8g-5j43-phc5), profile picture decompression DoS [GHSA-53gh-fffg-5f7f](https://github.com/pocket-id/pocket-id/security/advisories/GHSA-53gh-fffg-5f7f), and [GHSA-v5wr-7gfv-cv92](https://github.com/pocket-id/pocket-id/security/advisories/GHSA-v5wr-7gfv-cv92), fixed in 2.15.0. Upgrade to 2.19.1 with a digest pin. Run as UID/GID 1000, remove all capabilities, enable no-new-privileges and read-only rootfs, bound memory/processes and provide limited temporary storage. `deploy/security/update-pocket-id.sh` stops identity writers, backs up the entire data directory and key, updates only that service and waits for health. It does not recreate Fitsync. Production backup: `/var/backups/pocket-id-security-20261024T164728Z`. Before downgrading after migrations, restore both data and Compose from that backup with writers stopped.
- [HTTP2Shell / CVE-2026-111497](https://github.com/google/brotli/releases/tag/v1.2.1) concerns decoding malformed Brotli, including responses fetched by clients. The web builder used end-of-life Node 20; replace it with 24.22.1, a [patched Node release](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases). Production Aprendiendo runs Rust, not Node; reqwest's defaults are disabled and Brotli is not enabled. Its lockfile has no Brotli decoder. Stock Caddy enables gzip/zstd encoding here, with no Brotli module. No evidence of this specific decoder exposure was found in those production paths; this is not a claim about every other application on the shared host.
- RustSec detected vulnerable Rustls/Tokio/certificate verification dependencies. Update Rustls to 0.23.46, rustls-webpki to 0.103.16, Tokio to 1.54.1, webpki-root-certs to 1.0.11 and yanked chacha20 to 0.10.2. `cargo deny check advisories` passes after updates.
- Update compatible npm dependencies and override decode-uri-component and Zod to patched versions. Remaining npm audit findings all trace to **node-forge <=1.4.0**, [GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv), through Expo's build/code-signing tools. npm reports four high findings for this single chain; the registry has no patched node-forge release. Do not force npm's suggested downgrade to Expo 44. The production Rust service does not ship npm dependencies. Revisit when the upstream fix ships; avoid verifying untrusted signing certificates with this toolchain.
- Docker's context previously included deployment credentials, Pocket ID API key and Ansible secrets. Explicitly exclude these and private runtime directories. Refresh base images with `docker build --pull` in the release flow. Replace the obsolete nginx 1.27 web runtime with the maintained stable image.

## Verification and limits

Rust tests, advisory scan, shell syntax, TypeScript and web export are release checks. Verify the running Caddy version, identity container health/isolation, public health/readiness, OIDC discovery and unauthenticated MCP challenge after deployment. Only SSH and HTTP(S) are published; UFW is active for IPv4 and IPv6. Identity data/key ownership supports UID 1000. Existing encrypted shared-server backups remain in place.

This is a targeted security review, not a penetration test or a guarantee that no vulnerabilities remain. Passkey login requires a browser/user interaction and is not exercised by discovery or health checks. npm's unresolved node-forge issue remains open. The web image is a local preview stack, not part of the production Rust release.

## Bootstrap repair

The first release attempt exposed a legacy bootstrap assumption: Zeus uses Docker CE, while the playbook unconditionally installed Ubuntu's docker.io and docker-compose-v2. apt removed CE packages and then failed on the existing Compose plugin's file ownership conflict. Restored Docker CE/CLI/containerd.io and retained its Compose plugin. Bootstrap now checks installed packages, preserves CE, and refuses package removals when installing distro Docker on new hosts.
